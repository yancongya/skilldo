01 · THE MESS

You wrote one skill. Then copied it five times.

Every agent has its own skills folder, its own path, its own format. A skill you polished for one tool gets re-copied, re-tweaked, and forgotten everywhere else.

02 · THREE FORMS, ONE ENGINE

Terminal, desktop, or another machine.

The CLI and the desktop app share the exact same database and core engine. Use whichever fits the moment — state never drifts. SkillDo is one program: a desktop app you open, a CLI your agent calls, and a skill it discovers via SKILL.md. Same engine, three faces.

01 / CLI

The terminal is the dashboard

Install, sync, update, and publish skills with one command. Every command speaks --json — readable by you, and by the agent driving you.

  • Agent-native output — structured JSON on every subcommand
  • Standalone binary — curl one line, no Node, no runtime
  • Safe by default — destructive actions require --yes

03 · SINGLE SOURCE OF TRUTH

Edit once. Live everywhere.

The Central Repo holds the one canonical copy of every skill. Tools don't get copies — they get links pointing at it. Update in one place, and every tool sees the new version immediately.

symlink — macOS / Linux default, zero duplication
junction — Windows fallback, same semantics
copy — last resort for tools that reject links (e.g. Cursor)

04 · BUILT FOR AGENTS, FIRST

Not just used by you. Used by your agent.

SkillDo ships as a skill itself. Agents discover it via SKILL.md and drive the full lifecycle — install, sync, update — without you typing a thing.

Every command speaks JSON

Structured, machine-readable output on every subcommand — designed for agents to parse, decide, and act on.

❯ skilldo status --json { "tools": 45, "installed": 13, "detected": ["claude_code", "codex", ...] }

One command, repo-ified

Wrote a skill worth keeping? Publish turns a local folder into a tracked GitHub repo — future updates flow through the standard push path.

local skill→ skilldo publish→ git init→ create repo→ push
